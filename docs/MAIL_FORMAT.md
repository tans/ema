# EMA 邮件格式 v1

所有新出站邮件复用 `crates/core/src/email_format.rs`，纯文本呈现，系统文案跟随 EMA 的 `zh-CN` / `en` 设置；Agent 原始回复保持原语言。

## 类型与内容

| kind | 用途 | 主要内容 |
|---|---|---|
| `new_task_ack` | 新任务回执 | 指令摘要、排队或待补充信息状态、下一步 |
| `resume_ack` | 继续会话回执，包括首次回复 Hook | 本次指令、原会话关联、下一步 |
| `progress` | 执行进度 | 运行时长、最近观察到的活动；当前由 Codex runner 产生 |
| `result` | 执行结果 | 本轮结束或失败、Agent 回复或错误原因 |
| `error` | 未受理 | 明确未启动 Agent、稳定错误码、原因和处理建议 |
| `hook` | 本地会话报告 | Agent、项目、事件状态、指令、近期上下文、最终回复 |
| `test` | 发送测试 | 时间、验证范围；不创建任务，不要求回复 |

邮件类型、执行状态、SMTP 发送状态分别表达。正常退出只称“本轮结束”，不据此声称用户目标已完成。缺少最终回复时明确标注；不从 Agent 自由文本推断交付状态。

## 阅读顺序与标题

正文顺序：机器标记 → 一句话摘要 → 状态和项目等字段 → 主要内容 → 下一步 → 追踪信息。无关字段省略，必需但缺失的内容标注“未获取”。完整任务及会话 ID 放底部。

- 同一会话回复保持 `Re: <原主题>`，去掉重复 `Re:`，保留引用头关联。
- 独立 Hook：`[EMA][CODEX][本轮结束] ema · 任务标题`。
- 测试：`[EMA][连接测试] 邮件发送验证`。
- 主题清理换行、控制字符；原主题和独立报告标题最多 100 字符，回复另加 `Re: `。
- Hook 仅在有会话 ID 且适配器支持续接时提示直接回复；实际执行仍须通过权限、目录和 Agent 可用性检查。

## 机器协议与回环

每封邮件显式入库 `kind`；发送时校验类型，添加 `X-EMA-Kind`、`X-EMA-Message-Id`、`X-EMA-Version: 1`。正文首行：

```text
EMA-Message: v=1; kind=result; id=<ema-…@example.com>
```

标记随新邮件入库，SMTP 层幂等补齐。入站先识别 EMA 特征，再过滤自动邮件；首行有效标记可兜底邮件头丢失，原始 ID 命中本机 outbox 后建立改写 ID 映射。只识别首行完整标记，不扫描引用或正文中间的 `EMA-`。它用于自识别，不替代发件人授权。

新 Hook 通过结构化 `hook_context` 关联 Agent、原生会话和目录；旧记录保留原字段解析兼容。已发送历史邮件不重写；旧待发送邮件发送时补齐协议标记。

## 内容边界

指令最多 2,000 字符，主要回复最多 12,000 字符；超限显式提示截断。Hook 最多两条近期上下文，每条 1,000 字符，合计最多 2,200；旧事件的 context 字段最多 2,000。上游事件自身截断时仍提示截断。

不主动附加完整历史、原始事件或凭据；`EMA-Code:` 行统一脱敏。Agent 自由回复和底层错误仍可能包含敏感内容，发送前不代表已完成全面内容审查。

连接测试只用于验证本次 SMTP 投递，不能据此确认入站轮询、Agent 执行或真实会话续接成功。
